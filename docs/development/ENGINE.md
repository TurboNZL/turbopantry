# Engine

TurboPantry is pinned to [TurboNZL/turboengine](https://github.com/TurboNZL/turboengine) (`.turboengine.json`). The engine is a reference: modules are copied, not installed, apart from the `turbothemes` package, which is installed from the engine's `themes/` folder.

| Module | State | Where |
|---|---|---|
| `release-pipeline` | adapted: the `release` job (tag + GitHub release) and the `android` job (`turbopantry-<version>-android.apk`, attached to the release); the server is not a release asset. Signing: GitHub secrets if present, else the key committed in `apps/android` | `.github/workflows/` |
| `appearance` | in, renamed (storage prefix `turbopantry`, bridge names `turbopantryDesktop` / `TurboPantryAndroid`); layout `toolbar` and the player rules dropped | `apps/web/src/lib/appearance.ts`, `layout.ts`, `layouts.css`, `components/AppearanceCard.tsx`, `ThemeUpdates.tsx` |
| `guides-and-docs` | in; the guide table in `lib/guides.ts` lists TurboPantry's guides | `apps/web/src/lib/guides.ts`, `markdown.ts`, `components/GuidesTab.tsx`, `docs/guides/` |
| `settings-shell` | yes: wrapping tab strip and `Section` | `pages/SettingsPage.tsx`, `components/Section.tsx` |
| `self-hosted-server` | the mandatory set for an app with its own server; satisfied by the four rows below | |
| `server-install-update` | in. `scripts/install-pi.sh` and `scripts/update.sh` renamed (service/user/folder `turbopantry`, `TURBOPANTRY_*`, no ffmpeg/yt-dlp; the installer also makes the first account, and takes `--install-dir` so all of TurboPantry lives in one chosen folder: a candidate to port back to the engine). `update.ts` verbatim. `ServerUpdate.tsx` uses `useApi`. Differences from TurboMusic: accounts, so only the owner (first account) may update; the version shown comes from `git describe` | `packages/server/src/update.ts`, `index.ts`, `scripts/`, `apps/web/src/components/ServerUpdate.tsx`, `docs/guides/` |
| `cloudflare-access` | partly: `accessHeaders` in `lib/api.ts` and the Settings fields. `sse.ts` is in (live updates read the stream with fetch so the token and Access headers can be sent; `lib/sse.ts` verbatim, tested in `sse.test.ts`); `accessMedia.ts` is not needed yet (photos are hotlinked from other sites); `AccessProxy.kt` is in (`apps/android/.../AccessProxy.kt`, renamed package, wording only) | `apps/web/src/lib/api.ts`, `components/ServerCard.tsx` |
| `android-shell` | in, trimmed: `MainActivity` (WebView, edge-to-edge insets, asset loader, share-sheet target `ACTION_SEND text/plain` -> `/recipes/import?url=`, native "Update ready" dialog), `ServerPrefs`, `TurboPantryBridge` (`window.TurboPantryAndroid`: version, update, `setServer`, `setAccess`), manifest, build files. Left out: Media3, Android Auto, `NativeAudio`, `CuratorBridge` audio/Termux/haptics. Added by us (engine ships only `app/`): `settings.gradle.kts`, root `build.gradle.kts` (AGP 8.7.3, Kotlin 2.0.21), `gradle.properties`, resources | `apps/android/` |
| `updaters` | the Android half only (`update/AppUpdater.kt`, `Releases.kt`, with a JVM test); no Electron. The web Settings card (`native.ts`, `AppSettings.tsx`) is not taken yet | `apps/android/app/src/main/kotlin/nz/turbo/turbopantry/update/` |
| `device-pairing` | yes, with per-device tokens (server mints one per pairing; improvement for the engine) | `lib/pairCode.ts` (prefix `TP1-`), `components/ServerCard.tsx` (`PairCard`), `main.tsx` (`?pair=`), server `db.ts` (`device_tokens`), `extra-routes.ts` |
| `termux-server` | not yet (listed under `planned`) | |
| `layouts` | in (engine a6406d8): `floating` and `floating-rail` added to `lib/layout.ts` / `layouts.css` (the `bt-frame` class is on the row in `Layout.tsx`); the rest of the module (`AppShell.tsx`) is not taken, `Layout.tsx` is the app's own shell | `apps/web/src/lib/layout.ts`, `layouts.css`, `components/Layout.tsx` |
| `logos` | in (engine a6406d8; first fca5507). Small icons are the SYMBOL ONLY (rule 3): `out.symbolSvg` / `out.symbolPng` write `favicon.svg`, `favicon-32.png`, `favicon-48.png` (the jar alone, transparent); `index.html` lists them for the tab, and the 26-28 px logos inside the app use `/favicon.svg`. `icon.svg`, `icon-192/512.png`, the apple-touch icon, the manifest and the Android launcher stay the FULL mark; `favicon*` is not in the manifest. The shared TurboEngine mark with a **jar** emblem on the plate (a pantry jar with a slanted label band). Config `branding/logo.json`, emblem `branding/emblems/jar.json`, generator `scripts/gen-icons.mjs` + `scripts/logo/lib.mjs` (verbatim). Regenerate: `PLAYWRIGHT_MODULE=<playwright index.mjs> node scripts/gen-icons.mjs --png` (look at `--sheet`). `out.android` is set, so it also writes the launcher foreground/notification vectors and `ic_launcher_background` under `apps/android/app/src/main/res` | `apps/web/public/icon*.png/svg`, `apps/android/app/src/main/res`, `branding/` |
| `editions`, `window-frame`, `gpu-modes`, `discord-presence` | deliberately skipped (no Electron) | |
